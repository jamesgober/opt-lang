# opt-lang v0.2.0 — SSA Optimizations for ir-lang 2.0

**The foundation.** v0.2.0 turns the scaffold into a working optimizer for
`ir-lang` 2.0: sparse conditional constant propagation, global value
numbering, dead-code elimination, CFG simplification, copy propagation with
block-parameter elimination, and loop-invariant code motion, run as a
pipeline to a fixpoint with the IR validator between passes. Constant folding
follows the shared operation semantics exactly, policy by policy, and every
pass is iterative and budgeted. Behaviour is checked by running random
programs before and after optimization in ir-lang's reference interpreter.

## What is opt-lang?

The IR-to-IR stage of the `-lang` family's native compiler path: HIR lowers
into `ir-lang` 2.0, opt-lang rewrites it, and instruction selection reads the
result. It is a CODE-tier crate depending on `ir-lang` (`=2.0.0-alpha.1`) and
`pass-lang` (`1`). Not connected yet: no front end lowers into ir-lang 2.0 and
no backend reads it, so for now opt-lang runs on IR built directly with the
ir-lang `Builder` or parsed from its textual form.

## What's new in 0.2.0

### One call, or as much control as you want

```rust
use ir_lang::{Linkage, Module, Overflow, Signature, Type};
use opt_lang::{Optimizer, PassKind};

let mut m = Module::new("demo");
let f = m.declare_function("f", &Signature::new(&[Type::I64], &[Type::I64]), Linkage::Export)?;
let mut b = m.build(f)?;
let x = b.param(0)?;
let (two, three) = (b.iconst(Type::I64, 2)?, b.iconst(Type::I64, 3)?);
let k = b.add(two, three, Overflow::Wrap)?;
let y = b.mul(x, k, Overflow::Wrap)?;
b.ret(&[y])?;

// Tier 1: the default pipeline.
let stats = opt_lang::optimize(&mut m)?;
assert_eq!(stats.insts_after(), 2);

// Tier 2: chosen passes, sweeps, budget, validation between passes.
let stats = Optimizer::new()
    .passes(&[PassKind::Sccp, PassKind::Dce])
    .max_iterations(2)
    .budget(1 << 20)
    .validate(true)
    .run(&mut m)?;
assert_eq!(stats.insts_after(), 2);
# Ok::<(), Box<dyn std::error::Error>>(())
```

Tier 3 is `run_pass(&mut builder, PassKind::Gvn, &mut budget)` for callers
with their own pipeline.

### The passes

- **SCCP** propagates constants through instructions, block parameters, and
  only the edges that can be taken. `switch` and `check` edges are evaluated
  exactly: a `check` with constant operands goes to its normal edge with the
  value, to its error edge with the OPS error code, or becomes a `trap`; a
  `check` that cannot fail (a shift by a constant in range, a division by a
  constant other than `0` and `-1`, a widening `int_cast`, adding zero,
  multiplying by one) becomes the plain operation; and when a policy allows
  only one error kind, its code is a known constant on the error edge.
- **GVN** numbers pure operations in dominator-tree order, with commutative
  integer operands and comparisons canonicalized, and applies exact integer
  identities (`x + 0`, `x * 1`, `not(not(x))`, a `bitcast` round trip, ...).
- **DCE** removes dead instructions and dead block parameters, including loop
  variables that are only passed around, and keeps every side effect: calls,
  stores, atomics, fences, bulk memory, volatile loads, safepoints, and
  operations whose policy can trap.
- **CFG simplification** folds constant and trivial branches, prunes switch
  cases, removes unreachable blocks, threads jumps through empty blocks, and
  merges straight-line blocks.
- **Copy propagation** replaces block parameters that always receive the same
  value (loop-carried copies included) and removes them.
- **LICM** hoists pure loop-invariant operations into preheaders, creating
  them when needed, inner loops first.

### Folding that follows the policies

The folder gives, for constant operands, exactly what the reference
interpreter computes at run time, and is tested against its `eval_*`
functions over every operation, type, and policy. An operation whose `error`
or `trap` policy would fire is never folded into a value. A float arithmetic
result that is a NaN is left to run time (OPS allows any quiet NaN; folding
would fix one payload). `core` lacks `floor`, `round`, `sqrt` and friends on
Rust 1.85, so they are implemented from the bit representation and checked
bit for bit against `std`: `no_std` builds fold exactly like `std` builds.

### Safe around the garbage collector

A `ref`, and every pointer derived from one, is never made constant,
value-numbered, or hoisted, so no optimization can stretch it across a
safepoint. Random programs that carry references through safepoints,
branches, and loops are optimized, validated, and run.

### Budgeted, iterative, linear

Every pass charges its work to a `Budget` before doing it; a function whose
budget runs out is left valid and partly optimized (`Stats::budget_exhausted`).
No pass recurses over the input: 40,000-deep block chains, 10,000-deep
dominator trees, 300-deep loop nests, 20,000-case switches, and
3,000-parameter blocks are all in the tests. Because the ir-lang builder has
no instruction move and its `remove_block_param` scans every block, the
passes move instructions by re-inserting and forwarding, and remove many
parameters at once by rebuilding the affected blocks, both in linear time.

## Performance

x86_64, Rust 1.95 stable, release profile, Windows 11 (library only; the IR
is built outside the measurement):

| Benchmark | 100k instructions | 1M instructions |
|---|---:|---:|
| Whole pipeline to its fixpoint (3 sweeps) | ~69 ms | ~1.12 s |
| One SCCP run | ~16 ms | ~215 ms |
| One GVN run | ~11 ms | ~169 ms |
| One DCE run | ~5.6 ms | ~119 ms |

On the benchmark's typical shape (constant subexpressions, recomputed values,
dead values, diamonds, constant branches, loops with invariant products) the
pipeline removes 63.8% of the instructions and 63.0% of the blocks. That
shape is deliberately redundant; real code will see less.

## Verification

- Differential tests: random SSA programs (loops, `switch`, calls, `invoke`
  and landing pads, `resume`, checked arithmetic under every policy, floats
  including NaN, stack and global memory, volatile accesses, atomics,
  `memcpy`/`memset`, traps) run before and after optimization: the pipeline,
  each pass alone, and random pass sequences. Return values, trap codes,
  error codes, exceptions, import calls with their arguments in order, and
  final global memory must all match.
- The IR validates after every pass in every test; each pass, and the
  pipeline, is idempotent on every generated program.
- Per-pass unit tests on hand-written textual IR; GC programs; hostile shapes;
  budgets from zero up; scale tests at 100k and 200k instructions.

## Not in this release

Memory optimizations (redundant loads, store forwarding, dead stores),
inlining, SROA, loop canonicalization, strength reduction, and `fma` folding
are planned for 0.5.0; see `dev/ROADMAP.md`. Calls are never removed.

## Installation

```toml
[dependencies]
opt-lang = "0.2"
ir-lang  = "=2.0.0-alpha.1"
```

MSRV 1.85. `no_std` with `default-features = false` (needs `alloc`).
